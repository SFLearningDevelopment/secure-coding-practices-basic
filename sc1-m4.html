Before you begin

Cryptography protects data only when the right tool is used in the right way. This module covers the difference between encoding, hashing and encryption, how to store passwords, and how to make secrets that cannot be guessed.

Have Juice Shop ready, with the account you made in Module 1.

Theory: protecting data with cryptography

Encoding, hashing and encryption; data in transit and at rest; passwords; random numbers.

Encoding, hashing and encryption are different

What it doesCan it be reversed?Use it for
Encoding (Base64, URL encoding)Changes the format of dataYes, by anyoneMoving data safely between systems. Never for secrecy.
Hashing (SHA-256, Argon2id)Makes a fixed-length fingerprint of dataNoChecking data has not changed; storing passwords (with a slow password hash).
Encryption (AES-GCM, TLS)Scrambles data with a keyYes, with the keyKeeping data secret in transit and at rest.

Protecting data in transit

  • Use HTTPS (TLS 1.2 or later) for every page and API, including internal services.
  • Send Strict-Transport-Security so browsers never fall back to plain HTTP (Module 3).
  • Never turn off certificate checking in code, even "just for testing".

Protecting data at rest

  • Store only what you need. Data you do not keep cannot leak.
  • Encrypt sensitive data with a modern, authenticated algorithm such as AES-256-GCM, using the library your platform provides.
  • Keep keys out of the code and out of Git. Use a key management service such as AWS KMS or Azure Key Vault, and rotate keys.
  • Never write your own encryption algorithm, and never use ECB mode or reuse an IV (nonce) with the same key.

Storing passwords

Passwords are never encrypted and never stored with a fast hash such as MD5, SHA-1 or plain SHA-256. A fast hash lets an attacker test billions of guesses a second, and without a salt (random data added to each password) the same password always gives the same hash, so it can be looked up in a ready-made table.

Use a slow password hashing function, in this order of preference:

  1. Argon2id, with at least 19 MiB of memory, 2 iterations and 1 degree of parallelism.
  2. scrypt, if Argon2id is not available.
  3. bcrypt, for existing systems, with a work factor of 10 or more.
  4. PBKDF2 with HMAC-SHA-256 and at least 600,000 iterations, where only FIPS-approved algorithms are allowed.

These functions add a random salt for you and store it inside the hash string.

Random numbers

Session IDs, reset links, API keys and tokens must come from a cryptographically secure random generator. Ordinary random functions such as Math.random(), Python's random module, java.util.Random and System.Random are predictable.

This module maps to A04:2025 Cryptographic Failures. These are failures to protect data with cryptography, or using cryptography in a way that does not protect it.

Watch out

Base64 is not encryption. A value such as cGFzc3dvcmQ= in a config file or token is readable by anyone in one step.

Fixes: password hashing and secure random tokens

The same sign-up and reset code with the weakness and fixed, in each language.

The example is a sign-up and password-reset flow. It stores a password hash and creates a reset token. The fix in every language is to use a slow, salted password hash from a trusted library, and a secure random generator for tokens.

Node.js

The argon2 package (npm install argon2). Use crypto.randomBytes for tokens.

With the weakness

import { createHash } from "node:crypto";

const hash = createHash("md5").update(password).digest("hex");   // fast, no salt
const resetToken = Math.random().toString(36).slice(2);          // predictable

Fixed

import argon2 from "argon2";
import { randomBytes } from "node:crypto";

const hash = await argon2.hash(password, { type: argon2.argon2id });   // salted, slow
const ok = await argon2.verify(hash, attempt);

const resetToken = randomBytes(32).toString("hex");                    // secure random
JavaScript (browser)

In the browser, use the Web Crypto API for random values. Password hashing belongs on the server.

With the weakness

const id = Math.random().toString(16).slice(2);       // predictable
localStorage.setItem("pw", btoa(password));           // Base64 is not protection

Fixed

const id = crypto.randomUUID();                       // secure random
const bytes = crypto.getRandomValues(new Uint8Array(32));
// Never store passwords in the browser. Send them over HTTPS and let the server hash them.
TypeScript

The same as Node.js, with types.

With the weakness

function hashPassword(pw: string): string {
  return createHash("sha256").update(pw).digest("hex");   // fast, no salt
}

Fixed

import argon2 from "argon2";

async function hashPassword(pw: string): Promise<string> {
  return argon2.hash(pw, { type: argon2.argon2id });
}

async function checkPassword(hash: string, attempt: string): Promise<boolean> {
  return argon2.verify(hash, attempt);
}
Python

The argon2-cffi package (pip install argon2-cffi) and the secrets module.

With the weakness

import hashlib, random

hashed = hashlib.md5(password.encode()).hexdigest()       # fast, no salt
token = "".join(random.choices("abcdef0123456789", k=32)) # predictable

Fixed

import secrets
from argon2 import PasswordHasher

ph = PasswordHasher()                  # Argon2id with safe defaults
hashed = ph.hash(password)
ph.verify(hashed, attempt)             # raises VerifyMismatchError if wrong

token = secrets.token_hex(32)          # secure random
Java

Spring Security's password encoders, and SecureRandom for tokens.

With the weakness

MessageDigest md = MessageDigest.getInstance("MD5");
String hash = HexFormat.of().formatHex(md.digest(password.getBytes()));
String token = Long.toHexString(new Random().nextLong());

Fixed

PasswordEncoder encoder = Argon2PasswordEncoder.defaultsForSpringSecurity_v5_8();
String hash = encoder.encode(password);
boolean ok = encoder.matches(attempt, hash);

byte[] t = new byte[32];
new SecureRandom().nextBytes(t);
String token = HexFormat.of().formatHex(t);
C#

ASP.NET Core Identity's PasswordHasher (PBKDF2), and RandomNumberGenerator for tokens.

With the weakness

var hash = Convert.ToHexString(MD5.HashData(Encoding.UTF8.GetBytes(password)));
var token = new Random().Next().ToString("x");

Fixed

var hasher = new PasswordHasher<User>();
var hash = hasher.HashPassword(user, password);
var result = hasher.VerifyHashedPassword(user, hash, attempt);   // Success or Failed

var token = Convert.ToHexString(RandomNumberGenerator.GetBytes(32));
Recommended practice
  • When a user with an old MD5 or SHA-1 hash signs in successfully, re-hash their password with Argon2id and replace the old hash.
  • Compare secrets with a constant-time function, which password libraries do for you.
  • Keep encryption keys in a key management service, never in the code or in Git.

Lab: find a weak hash, then fix the hashing

Part A: decode the Juice Shop token. Part B: replace MD5 and weak random numbers in your language.

Part A: find a weak password hash in Juice Shop

Start Juice Shop on 127.0.0.1 and sign in with the account you made in Module 1. Use a made-up practice password, not one you use anywhere else.

  1. After you sign in, Juice Shop keeps a login token (a JWT) in the browser. Open the developer tools (F12), go to the Console tab and decode the middle part of the token:
const part = localStorage.getItem("token").split(".")[1].replace(/-/g, "+").replace(/_/g, "/");
JSON.parse(atob(part));
  1. Expand data. Find the password field. It holds a 32-character hex value.
  2. Work out the MD5 hash of your practice password on your own computer, for example:
node -e "console.log(require('crypto').createHash('md5').update('YOUR_PRACTICE_PASSWORD').digest('hex'))"

The two values match. Juice Shop stores passwords as plain MD5 with no salt, and it also puts the hash inside a token that the browser can read. Anyone with the same password has the same hash, and common passwords can be found in public MD5 lookup tables in seconds.

Think about it

Two mistakes are combined here: a fast, unsalted hash (A04), and sensitive data placed in a token that is only encoded, not encrypted.

When you are done, the output must be:

hash: (a long value, different every run)
same password, different hashes: true
right password accepted: true
wrong password accepted: false
token length: 64

import random

Java

This starter needs no extra libraries. Java includes PBKDF2 (SecretKeyFactory with PBKDF2WithHmacSHA256) and SecureRandom. Use a 16-byte random salt and 600,000 iterations, and store the salt with the hash.

HashDemo.java

import java.security.MessageDigest;
import java.util.HexFormat;
import java.util.Random;

public class HashDemo {
    // TODO: hash with PBKDF2-HMAC-SHA256 and a random salt instead of MD5
    static String hash(String password) throws Exception {
        MessageDigest md = MessageDigest.getInstance("MD5");
        return HexFormat.of().formatHex(md.digest(password.getBytes()));
    }

    static boolean verify(String stored, String password) throws Exception {
        return stored.equals(hash(password));
    }

    // TODO: use SecureRandom (64 hex characters)
    static String newToken() {
        byte[] t = new byte[32];
        new Random().nextBytes(t);
        return HexFormat.of().formatHex(t);
    }

    public static void main(String[] args) throws Exception {
        String password = "correct horse battery staple";
        String hash1 = hash(password);
        String hash2 = hash(password);
        System.out.println("hash: " + hash1);
        System.out.println("same password, different hashes: " + !hash1.equals(hash2));
        System.out.println("right password accepted: " + verify(hash1, password));
        System.out.println("wrong password accepted: " + verify(hash1, "wrong password"));
        System.out.println("token length: " + newToken().length());
    }
}

Hint

Node.js, TypeScript and Python use Argon2id libraries, which add the salt for you. Java and C# use the built-in PBKDF2, where you add the salt yourself and store it next to the hash, for example as iterations$salt$hash in Base64.
