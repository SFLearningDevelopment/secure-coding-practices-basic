Before you begin

This is the first of seven modules. By the end of the course you will be able to spot the most common weaknesses in web application code, explain which OWASP category each one belongs to, and fix it in the language you work in.

Each module has four sections. Tick the box at the end of a section when you have finished it. When all four are ticked and you have passed the check questions, you can mark the module complete.

You need a computer where you can install software. This module walks you through everything else.

1

How this course works

The format of each module, the languages used, and where the OWASP Top 10 fits.

From Module 1 onwards, each module covers one area of secure coding in four steps:

  1. Theory. What the weakness is, how attackers use it, and the recommended practices that prevent it.
  2. OWASP mapping. Which OWASP Top 10:2025 category the weakness belongs to, with the main CWE numbers.
  3. Fixes. The recommended fix, shown as code that has the weakness next to code that does not.
  4. Lab. A practical exercise where you find the weakness in a practice app and fix it.

Languages

Code examples are given in six languages: Node.js, JavaScript in the browser, TypeScript, Python, Java and C#. Each language has its own block, closed by default. Open the one you work in. You can also open several to compare them.

The OWASP Top 10:2025

The OWASP Top 10 is a list of the ten most serious risks to web applications, published by the Open Worldwide Application Security Project (OWASP). The 2025 edition is the current one. Each category groups several CWEs (Common Weakness Enumeration entries), which are numbered types of software weakness, such as CWE-89 for SQL injection.

Course 2 also covers the separate OWASP API Security Top 10, secrets management on GitHub, AWS and Azure, and penetration testing.

Good to know

CWE, CVE and CVSS are easy to mix up. A CWE is a type of weakness. A CVE is one specific weakness found in one specific product. CVSS is a score from 0 to 10 for how serious a CVE is.

2

Practising safely and legally

What you may test, and how to keep the practice apps away from other people.

In this course you will try real attacks, so that you understand what your code must stop. The same steps used on a system you are not allowed to test can be a criminal offence, for example under India's Information Technology Act, 2000 and similar laws in other countries. It is also against SourceFuse policy.

The rules

  • Test only what you own or have written permission to test. In this course, that means the practice apps running on your own computer, and your own GitHub, AWS and Azure accounts.
  • Never test client systems, SourceFuse systems or public websites as part of this course, even test or staging websites, and even to help someone.
  • Keep the practice apps local. Start them so they listen only on 127.0.0.1 (your own computer). Never deploy them to a cloud account or a shared server.
  • Use made-up data. Never put real customer data, real passwords or real access keys into a practice app or a lab.
  • Stop the apps when you finish. A deliberately insecure app should not run in the background.
Watch out

Using -p 3000:3000 with Docker makes the app reachable from every computer on your network, not only yours. Always use -p 127.0.0.1:3000:3000, as shown in this course.

Choose how to run the practice apps

Install one of four options. Option A suits most people.

OptionWhat you installRuns Juice ShopRuns crAPI

B. PodmanPodman Desktop or Podman, a free tool that runs the same container imagesYesYes
C. GitHub CodespacesNothing. Runs in your browser, on GitHub's serversYesYes

Option A: Docker

Install Docker Desktop from docs.docker.com/get-docker. On Linux you can install Docker Engine instead. Check that it works:

docker --version
docker compose version
docker run --rm hello-world   # prints "Hello from Docker!"
Good to know

Docker Desktop needs a paid licence in larger companies. Check with your IT team before installing it. If it is not allowed, use Option B, C or D.

Option B: Podman

Install Podman Desktop from podman-desktop.io, or Podman from your Linux package manager. On Windows and macOS, create and start the Podman machine when the installer asks. Podman uses the same commands as Docker, so wherever this course says docker, you can type podman.

podman --version
podman run --rm hello-world
podman compose version        # needed for crAPI

Option C: GitHub Codespaces

A codespace is a computer in the cloud that you use from your browser. Docker is already installed in it.

  1. Sign in to GitHub with your own account and create a new empty private repository, for example secure-coding-labs.
  2. On the repository page, select Code, then the Codespaces tab, then Create codespace on main.
  3. In the terminal of the codespace, run docker run --rm hello-world.

When an app starts in the codespace, the Ports tab shows a link to open it. Leave the port Private, which is the default, so that only you can open it.

Watch out

Never change a practice app's port to Public. GitHub gives each account a limited number of free hours a month, so stop the codespace when you finish.

Option D: Node.js only (Juice Shop only)

Install Node.js (see Section 4). Then download the Juice Shop release for your operating system and Node.js version from github.com/juice-shop/juice-shop/releases, unzip it, and start it:

cd juice-shop_<version>
npm start                     # then open http://localhost:3000

With this option you cannot run crAPI. You will need Option A, B or C for the API labs.

4

Lab: start the practice apps and set up your language

Run Juice Shop and crAPI on your own computer only, and check the tools for the languages you work in.

1. Start Juice Shop

docker run --rm -d --name juice-shop -p 127.0.0.1:3000:3000 bkimminich/juice-shop
docker ps                     # juice-shop shows 127.0.0.1:3000->3000/tcp

Open http://localhost:3000. You should see the Juice Shop home page with a list of products.

2. Start crAPI

crAPI runs as several containers, started together with Docker Compose. By default it listens only on your own computer.

mkdir crapi && cd crapi
curl -o docker-compose.yml https://raw.githubusercontent.com/OWASP/crAPI/main/deploy/docker/docker-compose.yml
docker compose pull
docker compose -f docker-compose.yml --compatibility up -d
docker compose ps             # wait until every service shows "healthy"

Open http://localhost:8888 to see the crAPI sign-up page. crAPI sends its emails to a test mailbox at http://localhost:8025.

Watch out

Do not set LISTEN_IP=0.0.0.0 when you start crAPI. That setting makes it reachable from other computers.

3. Set up the language you work in

Set up at least one language. Open the block for each language you want to use.

Node.js

Install the current LTS release from nodejs.org. Version 22 or later is fine. npm is installed with it.

node --version     # v22 or later
npm --version
JavaScript (browser)

You need only a current browser: Chrome, Edge or Firefox. Open the developer tools with F12 (or Cmd+Option+I on macOS) and go to the Console tab.

console.log("Browser console is ready");

Later modules use the Network and Application tabs as well, to look at requests, cookies and storage.

TypeScript

TypeScript runs on Node.js, so install Node.js first (see the Node.js block). Then create a practice folder:

mkdir sc-ts && cd sc-ts
npm init -y
npm install --save-dev typescript
npx tsc --version  # Version 5 or later
Python

Install Python 3.12 or later from python.org. Use a virtual environment for each practice folder, so packages stay separate.

python3 --version              # 3.12 or later (on Windows: py --version)
mkdir sc-py && cd sc-py
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip --version
Java

Install a JDK, version 21 or later. Eclipse Temurin from adoptium.net is free. Later labs use Maven, which you can install from maven.apache.org.

java -version      # 21 or later
javac -version
mvn -version
C#

Install the .NET SDK, version 8 or later, from dotnet.microsoft.com/download. Then create and run a small console app:

dotnet --version   # 8 or later
dotnet new console -o sc-cs
cd sc-cs
dotnet run         # prints Hello, World!

4. Stop everything

docker stop juice-shop
cd crapi && docker compose down

Start them again in the same way at the start of each lab.

Check your work
  • docker ps showed Juice Shop on 127.0.0.1:3000, not 0.0.0.0:3000
  • The Juice Shop home page and the crAPI sign-up page both opened in your browser
  • The version check for at least one language printed the expected version
  • Both apps are stopped
